01Moment oneWeek 0

The day the silicon comes back.

The board is on the bench. The fans spin up. Years of work, and it works. It’s fast. It’s efficient.

Then someone asks what it runs. The honest answer: nothing your customers use. Not yet. Nobody has written that software.

What FuseZap does

First, an honest map of where you stand.

We run our operation tests on your toolchain or your functional simulator. You get an op-coverage report: what runs today, and what it would take to get the rest.

You bring a kernel compiler and a driver. We bring the engine, the server and the checks.

02Moment two · The first customer questionCore & Serve Apache-2.0

Will it run Llama?

It’s the first thing they ask. Not about your memory, not about your roadmap. Will it run the model we picked last week?

Too often the answer is “not yet”. The software the world runs models on was built for NVIDIA first, and every other chip waits its turn.

What FuseZap does

One backend for your chip. Everything above it stays the same.

Models break down into 28 basic operations. Core generates the code for your chip from those, so a new chip needs one backend, not a port of a whole framework. Today that means text models built like Llama, Qwen and Mistral: not yet mixture-of-experts, sliding-window attention or image models.

How Core & Serve work →

03Moment threeSteps 1 and 2

The first token.

It’s late, and the room has gone quiet. A prompt goes in. One token comes back from your silicon.

Everyone leans in. Is it the right one?

What FuseZap does

Right first. Then served.

First, a model that matches a full-precision reference, token for token. So when that first token appears, you already know whether it’s right.

Then FuseZap Serve puts it behind the API your customers already call, with streaming, tool calls and structured output.

04Moment fourValidate Licensed

Every release after that.

Launch day isn’t the finish line. A new driver lands. The compiler moves. A customer wants a new model by Friday.

Each one is a small bet. Did the answers change? Did tool calls break? Did it get slower? Too often, a customer is the first to know.

What FuseZap does

One word before every release, and the evidence behind it.

Validate ends in PROMOTE, BLOCK or REVIEW, and exits with a code your CI can read. It works with any OpenAI-compatible server, whether or not you run Core. A Friday release goes back to being just a Friday release.

PROMOTE

Nothing failed on the checks that ran. Ship it.

BLOCK

A check failed on valid data, against a fixed bar or against the release you approved last time.

REVIEW

Too close to call, or something couldn’t be measured. A person should look.

  • AnswersEvery token checked against a full-precision reference.
  • Tool calls and JSONEach failure named: a number sent as text, a missing field, the wrong tool.
  • Long promptsFacts hidden deep in the prompt, to see whether the model still finds them.
  • SpeedFirst token, time per token and throughput, with confidence intervals.
  • Under pressureOverload, cancelled requests and a restart.
  • Against last timeEverything compared with the release you approved before.

The FuseZap Bring-Up Program

From your toolchain to your customers’ API.

You bring a kernel compiler and a driver, or a functional simulator. We bring the engine, the server and the checks, and build your chip’s backend side by side with your team.

  1. 0Week 0

    Op-coverage report

    We run our operation tests on your toolchain or simulator: what runs today, and what it would take to get the rest.

  2. 1Correct

    First model correct

    One backend for your chip, and a first model that matches a full-precision reference token for token.

  3. 2Served

    Behind the OpenAI API

    FuseZap Serve puts it behind the API your customers already call, with streaming, tool calls and structured output.

  4. 3Guarded

    Validate in your CI

    Every driver, compiler and model change gets PROMOTE, BLOCK or REVIEW before it reaches a customer.

We aim for weeks to a first model, not quarters. After the week-0 report, we’ll give you an honest estimate for yours.

What you bring

  • A kernel toolchain that can compile a kernel, launch it and manage device memory, or a functional simulator with the same interface
  • One engineer who knows that toolchain
  • The models your customers ask for

What you keep

  • An Apache-2.0 backend for your chip that you own, handed over with its tests
  • A place on the model × chip matrix, with dated evidence for every cell
  • Validate on your releases, so each one ends in PROMOTE, BLOCK or REVIEW
