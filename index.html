PROMOTE

Every gate in the checks you ran passed on valid data. Skipped gates are listed, each with its reason.

BLOCK

A check failed on valid data, against a fixed bar or against the release you approved last time.

REVIEW

Too close to call, or a check ran but couldn’t measure something. A person should look.

  • AnswersEvery token checked against a full-precision reference.
  • Tool calls and JSONEach failure named: a number sent as text, a missing field, the wrong tool.
  • Long promptsFacts hidden deep in the prompt, to see whether the model still finds them.
  • SpeedFirst token, time per token and throughput, with confidence intervals.
  • Under pressureOverload, cancelled requests and a restart.
  • Against last timeEverything compared with the release you approved before.

The FuseZap Bring-Up Program

From your toolchain to your customers’ API.

You bring a kernel compiler and a driver, or a functional simulator. We bring the engine, the server and the checks, and build your chip’s backend side by side with your team.

  1. 0Week 0

    Op-coverage report

    We run our operation tests on your toolchain or simulator: what runs today, and what it would take to get the rest.

  2. 1Correct

    First model correct

    One backend for your chip, and a first model that matches a full-precision reference token for token.

  3. 2Served

    Behind the OpenAI API

    FuseZap Serve puts it behind the API your customers already call, with streaming, tool calls and structured output.

  4. 3Guarded

    Validate in your CI

    Every driver, compiler and model change gets PROMOTE, BLOCK or REVIEW before it reaches a customer.

We aim for weeks to a first model, not quarters. After the week-0 report, we’ll give you an honest estimate for yours.

What you bring

  • A kernel toolchain that can compile a kernel, launch it and manage device memory, or a functional simulator with the same interface
  • One engineer who knows that toolchain
  • The models your customers ask for

What you keep

  • An Apache-2.0 backend for your chip that you own, handed over with its tests
  • A place on the model × chip matrix, with dated evidence for every cell
  • Validate on your releases, so each one ends in PROMOTE, BLOCK or REVIEW
