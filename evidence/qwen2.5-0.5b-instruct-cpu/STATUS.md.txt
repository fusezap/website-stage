Design (fusezap/serve/dist.py): one process per device, Megatron sharding. Rank 0 runs the API, tokenizer, scheduler
and sampling; every model call it makes (an LLMEngine forward with its host arrays, Llama.prefill / decode / reset, the
logprobs scorer, the allocator release) is sent to the workers first (`TPGroup.spmd`), which run the same call on their
shards; workers have no scheduler. q/k/v (+ biases) and gate/up are column-parallel by head group / intermediate dim,
o_proj and down_proj row-parallel followed by an all-reduce (then the bias once); norms, embedding and lm_head are
replicated (a worker's logits equal rank 0's, so CUDA lookahead feeds each rank its own device argmax). Each rank reads
only its slices from the mmap'd safetensors. The all-reduce is a kind="custom" ScheduleItem (`AllReduceCall`) through
`fz.jit.run_item`, so the jitted forwards record and replay it like the serve kernels; on CUDA ncclAllReduce runs on
the device's current stream, so the CUDA-graph capture of a step captures the NCCL kernels too (full graphs with TP,
nothing segment-wise). Backends: NCCL via ctypes (CUDA), host sockets (any device; the Mac proof). A worker that exits,
or a mirrored call that fails on rank 0, stops rank 0 (exit 1) instead of hanging it.

Mac evidence (METAL, host backend, 2 processes): tiny random Qwen2 (4/2 heads, q/k/v + o biases) TP=2 prefill and
decode logits == TP=1 within 1e-4, engine tokens identical; Qwen2.5-0.5B f32 TP=2 greedy 32 tokens x 3 prompts ==
TP=1; `fusezap serve --tp 2`: chat, streaming, echo logprobs, cancel (running gauge back to 0), killed worker -> the
server exits 1 within seconds. On CUDA: `scripts/tp_m1_cuda.sh` (one 2x RTX 4090 pod, NCCL_P2P_DISABLE=1).

The M1 CUDA hang: TPGroup.close sent "quit", then waited 30 s for the worker before releasing its own communicator; the
worker, on "quit", called ncclCommDestroy, which since NCCL 2.18 is an intra-node collective that waits for every rank
to destroy too. So the worker waited for rank 0, rank 0 waited for the worker, killed it after 30 s, then called
ncclCommDestroy itself and waited forever for the dead peer (pytest exit 124 after the 1200 s timeout). Now both ranks
use ncclCommAbort (local, as torch's ProcessGroupNCCL.shutdown), rank 0 aborts before it waits for the workers, every
step (send quit, synchronize, abort, wait, kill) is bounded, and a worker leaves with os._exit. The engine process
closes the group and exits right after its last message. Not yet confirmed on GPUs: tp_m2_70b.sh runs the CUDA TP tests
first (`-v`, faulthandler_timeout, pytest-timeout, FZ_TP_DEBUG=1).
