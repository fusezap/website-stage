Why a release check

A small bet, turned into a check.

You ship a model server. Maybe it’s vLLM with your own patches, maybe it’s an engine you wrote. Then the engine moves. A new driver lands. The compiler changes. A customer wants a new model by Friday. Each change is a small bet that nothing broke, and too often a customer is the first to find out.

Validate runs before they do. It calls your server the way they would, then tells you, in one word, whether to ship.

It works with any OpenAI-compatible server, and you don’t need FuseZap Core. We’ve tested it on vLLM, SGLang, TensorRT-LLM, TGI and a hosted API (Fireworks), as well as on FuseZap.

01Chapter one · A real runOctober 2026

What it found
in October.

We ran Validate against vLLM on two popular open models across two H200s. Qwen2.5-72B passed everything and got PROMOTE.

The other 70B model passed accuracy and reliability, then got BLOCK: only 51 of its 93 tool calls were right. Again and again it sent numbers and true/false values as text where the tool expected a number. With strict tools turned on, 77 of 81 calls were right.

That’s the kind of difference you want to know about before a customer’s agent does.

What Validate does

Name the failure, not just the score.

Every failed tool call is recorded with what went wrong: a number sent as text, a missing field, the wrong tool. Open the card to see what this one looks like.

02Chapter twoHow it works

Run it like a customer.

You shouldn’t have to send weights, prompts or results outside your own network to qualify a release. Validate runs inside your environment, against the same endpoint your applications already call.

And because it compares against the saved report from your last good release, you don’t need a second cluster sitting idle just to keep the old one running.

What Validate does

Compare twice.

Against a full-precision reference, so you can see how far accuracy drifted, and against the release you approved last time, so you can see what changed.

  1. 1Config

    Describe the release

    One config file: the server, the models, the loads you care about, and the release you approved last time.

  2. 2Run

    Run it like a customer

    Validate calls your OpenAI-compatible server the way your customers do, from your own systems. Nothing calls home.

  3. 3Compare

    Compare twice

    Against a full-precision reference, and against the stored report of the release you approved.

  4. 4Decide

    One word

    PROMOTE, BLOCK or REVIEW, with a report and an exit code your CI already understands.

03Chapter threeWhat it looks at

Six checks, the way your customers would notice.

Each check is a question a customer would ask the hard way. Is it still right? Does it still call my tools? Is it still fast? Does it survive a bad day?

  1. 01AnswersEvery token checked against a full-precision reference, so you see accuracy drift, not just a pass or fail.
  2. 02Tool calls and JSON101 tool-call tasks and 50 JSON tasks, with each failure named: a number sent as text, a missing field, the wrong tool.
  3. 03Long promptsFacts hidden in prompts of up to 32,768 tokens, to see whether the model still finds them.
  4. 04SpeedTime to the first token, time per token and throughput at the loads you choose, with confidence intervals so noise doesn’t look like a regression.
  5. 05Under pressureOverload, cancelled requests, abandoned connections and a restart, to see whether the server recovers cleanly.
  6. 06Against last timeEverything compared with the release you approved before, kept as a stored report, so the old release doesn’t need to stay running.
04Chapter fourThe decision

One word, with the evidence.

A word you can trust has to be able to say “I don’t know”. That’s what REVIEW is for: when the evidence is too close to call, a person decides, not a coin flip.

Your release manager reads the word. Your engineers read the gates. Your CI reads the exit code. Everyone is looking at the same evidence.

The rules behind every verdict →

PROMOTE

Nothing failed on the checks that ran. Ship it.

BLOCK

A check failed on valid data, either against a fixed bar or against the release you approved last time.

REVIEW

Too close to call, or something couldn’t be measured. A person should look.
