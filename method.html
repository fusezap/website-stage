Why rules

Speed is easy to love.

It’s the number everyone asks about first. It’s also the easiest one to get wrong without noticing: a model can get faster and quietly worse in the same release.

So before any number leaves the lab, it has to pass six rules. They aren’t clever. They’re just never skipped.

The same rules decide every Validate verdict on your releases.

The six rules

What every number has to pass.

Each rule has one example from our own runs. The detail behind each one is in the engineering notes.

  1. 01Rule one1 of 6

    Check against full precision.

    Before we publish a speed number, the model is checked token by token against a float32 reference.

    For example

    On Qwen2.5-7B on one H100, FuseZap picks the same next token as the reference 99.6% of the time.

  2. 02Rule two2 of 6

    Compare with the release you approved.

    A new release is judged against a stored report of the last one you approved, not against memory. The old release doesn’t need to stay running.

    In Validate

    Seven of the sample report’s gates compare with an approved release. That run had none, so they were skipped, and the report says so.

  3. 03Rule three3 of 6

    Let the interval decide.

    Rates such as tool-call validity are judged on 95% confidence intervals: a pass needs the whole interval to clear the bar. When the result is too close to call, the answer is REVIEW and a person decides, not a coin flip.

    The words

    PROMOTE when the whole interval clears the bar, BLOCK when it falls short, REVIEW when it straddles the bar (Fig. 1).

  4. 04Rule four4 of 6

    Bit-identical where we say so.

    When we claim a change doesn’t change the answers, we check it bit for bit.

    For example

    32 requests served together produce exactly the tokens each produces alone. Our rewritten Inferentia2 prompt kernels give the same results as the old ones, bit for bit.

  5. 05Rule five5 of 6

    Same machine, or say so.

    Comparisons run back to back on the same machine where we can, because machines of the same type differ by a few percent. When they don’t, the note says so.

    For example

    Qwen2.5-7B on one H100, back to back with vLLM on the same machine: 5.57 ms a token against 5.85.

  6. 06Rule six6 of 6

    Publish the gaps.

    Every target we haven’t met is on the status page, next to what we measured.

    Why

    You’ll find the gaps anyway. It’s better that you hear them from us first.
